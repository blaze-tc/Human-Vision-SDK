# RK3588 联合优化包：一次自动对照

本包用于同一次安装内对照原路径与候选优化。目标是减少预览被识别占用、
GPU 回读和 RKNN 输入开销，同时保持真实骨骼的位置与帧身份。20–25 FPS
仍需 RK3588 实测确认；OnePlus 的 Vulkan 结果不能代替 NPU 验收。

界面左侧优先显示完整视频，日志与硬件信息位于右下方。画面保持比例，骨骼与
区域框跟随同一个视频矩形；右侧设置可滚动，放大画面后再次点击可恢复布局。

## 设备操作

1. 安装提供的联合测试 APK，进入 **HumanVisionSettingsDemo**。
2. 在 RTSP 页填入设备实际使用的摄像头地址，确认人数等配置。自动对照读取
   当前草稿，不要求保存；视频使用 APK 内打包的第一段测试视频。
3. 点击底部 **一键自动对照**。RK3588 全程约 15–20 分钟，期间保持应用前台，
   摄像头内让实际使用人数连续活动；无需中途切换安装包或切换模式。
4. 等待显示对照结束。点击 **复制日志文件夹**，直接取走该整个目录。
   Android 公共目录通常为 `Download/HumanVisionLogs/session-时间-标识`。
   公共副本约每 5 秒刷新；结束后等待一次刷新再复制。

停止自动对照会安全停止当前阶段并恢复原草稿/运行状态。未完成阶段会在分析
中标记为中断。程序不会把中断、没有人体或不可用硬件计为验收成功。

## 自动对照内容

- GPU 像素检查：三种源尺寸及镜像，比较所有模型 RGB 字节。
- RTSP 仅预览：不运行识别，记录实际预览发布数。
- 本地视频、RTSP：RK3588 依次运行 NPU 基线、候选、重复基线。
- 最后持续运行本地视频 300 秒，记录温度变化和长期性能。
- 每阶段先预热 15 秒，普通测量 60 秒。OnePlus 等设备明确跳过 RKNN，
  使用 CPU / Vulkan 检查公共输入链路与播放功能。

“candidate”表示请求候选路径，不代表候选已启用。检查原生日志的 `input_path`
以及 `cpuReadback.modelReadback`。共享 RKNN 输入必须通过同帧完整输出一致性与
耗时门槛，缩小回读必须通过设备上连续三帧完整 RGB 一致性；不通过时保留基线。
RGA 路径目前不启用。

2026-10-11 增加原生 FP16 输入与输出内存复用候选，同一包会在不支持或未通过
检查时依次尝试共享 UINT8 输入/输出、共享输入、原基线。模型文件没有更换。
原生日志中 `native-fp16-io-qualified`、`shared-io-qualified`、
`shared-input-qualified` 表示实际选中路径；`legacy-*` 表示正在检查或保留基线。
`baseline_ms` / `candidate_ms` 是同帧后端比较值，`previous` / `reason` 保存上一个
未通过的候选及原因。它们不能替代 `persons` 中逐人真实骨骼帧率。

## 日志判读

自动对照运行期间会锁定配置，防止中途切换计算模式污染对照数据。左侧状态条
会明确提示锁定；右下 **停止对照 / 解锁设置** 可随时取消，等待当前输入安全
停止和原配置恢复后继续手动操作。日志文件夹复制和导出保持可用。组件禁用或
测试异常退出也会释放界面锁定；普通运行不会自动锁住下拉框。

左侧底部显示 **输入 / 新结果 FPS**：分别统计不同输入发布帧和 SDK 接受的不同
来源帧结果，包括明确无人结果。该统计适用于 CPU、Vulkan 和 NPU，不依赖旧版
原生 FPS 字段；重复帧不计数，停止/换源重置，停流窗口归零。它不是逐人完整骨骼
验收值；逐人观测仍以 `persons` 文件为准。SDK API 对应
`InputPublicationFps` / `FreshResultFps`。

`events` 保存阶段边界和错误；`persons` 保存逐稳定 ID 的真实观测/完整 COCO-17
计数与本地延迟；`timings`、`native` 保存阶段耗时；`hardware` 保存硬件状态。
Android 文件名可能追加 `.txt`，内容格式不变。

仓库中运行：

```text
python tools/benchmark/analyze_combined_benchmark.py SESSION_FOLDER combined.json
python tools/benchmark/analyze_settings_device_log.py SESSION_FOLDER pipeline.json --warmup 15
```

第一份报告排除预热、像素检查和未完成的测量，重复基线分开统计。第二份给出
供帧、GPU 回读、模型执行与硬件的分段数据。GPU/NPU 利用率是辅助诊断信息，
不代替逐人新骨骼帧率；缺失遥测表示不可用，不是零负载。跟随坐标仍须结合
实机录像判断，完整 COCO-17 计数也不等同于完整 32 点骨骼精度。
