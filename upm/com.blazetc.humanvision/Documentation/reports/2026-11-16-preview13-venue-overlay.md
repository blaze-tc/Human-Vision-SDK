# preview.13 场地预览同帧修复

当场地设置页使用常驻 Runtime Prefab 且开启骨骼时，预览显示该骨骼结果对应的输入纹理。骨骼关闭或暂时没有有效同帧结果时显示实时输入。
启用后的同帧图像随新结果更新。它的显示帧龄仍包含快照、异步回读、推理和 Unity 读取耗时。

使用 Windows Unity 2021.3.45f1、DancingTest RTSP、CPU 低档 512×288 和四个区域进行了修复前后对照。
两次各预热 6 秒，测量约 24 秒，按实际显示的 RawImage 纹理、源帧编号和可见骨骼网格校验。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 有可画骨骼时，实际图像与骨骼同源帧 | 0/430 | 435/435 |
| 图像与骨骼的源时间差 P50 | 101.345 ms | 0 ms |
| 图像与骨骼的源时间差 P95 | 300.268 ms | 0 ms |
| SDK 接受的新结果 | 17.997 FPS | 18.072 FPS |
| 骨骼结果年龄 P50 | 116.415 ms | 116.053 ms |

同帧 PlayMode 回归覆盖关闭骨骼时的实时预览和停启后的来源隔离。以上数据来自此前的 Windows 修复验证。
RK3588 的持续新骨骼率、端到端时延和跳跃或冲刺响应需要在目标设备和业务现场分别验收。

本版包含已接入的三档 RK3588 NPU 支持。对应 RKNN 模型和 `librknnrt.so` 由本地补充包提供。
三档验收的已有数值和打包证据见[三档接入报告](https://github.com/blaze-tc/Human-Vision-SDK/blob/v0.4.0-preview.13/docs/reports/2026-11-11-rk3588-npu-qualities.md)。
