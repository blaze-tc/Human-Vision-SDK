# Human Vision SDK 0.4.0 正式版：改动与验证范围

SDK **0.4.0**、Input **0.1.0**，两包统一使用 Git 标签 **v0.4.0**。
Unity 2021.3+；Windows x64、Android ARM64/API26。先安装Input，再安装SDK。
本次正式版本指代码、接口与配套包版本，不改变随附模型的许可证和评估/分发资格标记。

## 主要改动

- 原生RTSP输入、处理与完成驱动发布可脱离Unity逐帧推进，CPU/GPU/NPU共用Runtime调度。
- 同decoder独立有界live与analysis出口，最新帧优先，避免未处理旧帧持续排队。
- 普通SDK RTSP颜色Texture保持实际解码后的可见原尺寸，Windows/Android兼容和独立路径都保持用户URL；模型缩放仅用于识别。明确Analysis接口保留分析语义。
- Android实时预览经GPU纹理与真实fence交接，摆脱旧5Hz CPU高清预览通道。Windows按真实尺寸配置预览，避免同一帧重复像素上传。
- 兼容Unity 2021无async compute的graphics fence查询；修复黑屏、预览暂停和拍照后配对槽未释放导致持续降速。
- 普通业务与Demo每Update直接查询SDK当前有效坐标，无需FPS、FrameId、ResultSequence或分析Texture前置判断。SDK统一处理来源、时效与关节置信度。
- Runtime Prefab右侧单个原图预览叠加区域与骨骼，左侧控制和日志分别滚动；保留后端/模型/人数/区域/设置/生命周期/全屏/精确照片/诊断功能。
- 五项统计分别是源解码、Texture更新、送入识别、识别完成和有效骨骼交付，缺测显示未知。
- 保留旧C V1、Plugin ABI与Unity主线程事件语义，新增控制和图像能力采用版本化扩展。

公开Android SDK按同一源码独立构建，显式关闭私有RKNN厂商实现与实验开关。实际API26强导入、导出和依赖闭包审计独立于手机完整本地候选；不能把其字节身份混为一谈。

Android完整CPU/NPU资源、RKNN-ON SDK、`librknnrt.so`、私有模型、设备APK和用户视频不在公共Release附件中。本次完整本地替代SDK与公开SDK使用同一package id和GUID；需要它时替换SDK安装，不在Git SDK旁再导入另一套Assets SDK。Input仍使用正式0.1.0。具体以配套本地manifest的模型、原生库和源提交哈希为准，不能沿用preview.17补充包覆盖新库。

## 已有功能验收与发布闸门

本轮候选源码回归：原图阶段SDK原生576/576；恢复已发布Windows的39个名称和原ordinal后原生578/578（新增实际DLL ABI两例先RED再GREEN），新控制查询仅追加于ordinal40。Input原生66/66、实际Unity150/150（0失败/跳过）、包快照15/15；旧失败记录保留，不以定向通过倒推历史391项整批通过。

Windows与OnePlus9Pro完整本地候选已验证1920×1080原图、独立模型尺寸、Update取点及1920×1080精确照片。拍照前20秒/后5–35秒/后35–65秒，同源Texture平均24.55/22.73/22.37 FPS，源解码约30，原生错误0；该设备窗口使用RKNN-ON本地SDK，未复现修复前持续5–7FPS，但不保证恒定30Texture或全部识别吞吐不变。

正式公共包另以Input-first离线/UPM真实导入、Windows实际模型初始化、输入隔离、版本/资产/GUID闭包、API26依赖、公开接口和架构检查作为发布闸门。从最终提交生成两tgz、两unitypackage、README、资产索引、源快照和SHA256SUMS八个公共文件，上传草稿后重新下载逐一校验，再发布非prerelease版本。最终提交与下载哈希以Release附件`source-snapshot.json`和`SHA256SUMS.txt`为准；发布检查回执见仓库发布验证记录。

原生自主来源当前是RTSP；VideoPlayer/WebCamTexture仍为Unity兼容入口。RGA未实现，RK3588硬件、长时热稳定、联合业务GPU负载、原生相机/文件driver、完整手部与每人30完整骨骼FPS不计通过。线程/队列分离仍共享物理GPU、带宽和功耗预算。World坐标为图像到Unity平面的映射，不是实测深度。
